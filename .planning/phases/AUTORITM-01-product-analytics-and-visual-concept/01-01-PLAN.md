<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Participant → facilitator notes | A participant's explanation and optional quote could reveal personal information unless notes are minimised and consented. |
| Product wording → owner maintenance choice | A manual deadline could be misread as verified maintenance advice. |
| Documentation → later implementation | A design artifact could be wrongly treated as authorisation for tracking, collection, or an external data claim. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Information disclosure | Observation protocol | medium | mitigate | Task 3 requires consent, a participant code, typed minimal notes, stated retention/deletion, and anonymised quotations. |
| T-01-02 | Spoofing / tampering | Due-status and copy contract | medium | mitigate | Task 2 requires reason-specific text, a non-colour cue, and the user-entered deadline/vehicle-manual disclosure. |
| T-01-03 | Information disclosure | Analytics scope | medium | mitigate | Task 3 confines evidence to manual, blank observation rows; no collection mechanism, identifier, credential, or transmission is specified. |
| T-01-04 | Repudiation | Study evidence | low | mitigate | Task 3 records task context and participant code while retaining blank outcomes until a consented session. |
| T-01-SC | Tampering | Package installation | low | mitigate | No package-manager action or dependency is authorised; implementation must keep the dependency-free documentation scope. |
</threat_model>
