# АвтоРитм

## What This Is

АвтоРитм — локальный mobile-first веб-прототип личной сервисной книжки для частного владельца автомобиля в России. Он помогает сохранить данные одной машины, спланировать обслуживание по дате или пробегу и вести историю расходов без таблиц и бумажных заметок.

## Core Value

Владелец в любой момент понимает, что уже сделано с автомобилем, что требует внимания следующим и сколько это стоило.

## Business Context

- **Customer**: частный владелец одного автомобиля в России.
- **Revenue model**: не определён — учебный MVP не монетизируется.
- **Success metric**: пользователь без подсказки создаёт автомобиль, планирует ТО и добавляет выполненную работу.
- **Strategy notes**: `PRD.md`.

## Requirements

### Validated

- ✓ Пользователь может сохранить карточку автомобиля в браузере — существующий прототип.
- ✓ Пользователь может вручную создать план работы с датой или пробегом — существующий прототип.
- ✓ Пользователь может добавить запись о работе и расходе и увидеть итог — существующий прототип.

### Active

- [ ] Продуктовый контекст, UX-путь, пользовательские истории и визуальные правила оформлены в файлах, пригодных для следующего агента.
- [ ] Основной сценарий «автомобиль → план ТО → запись о выполненной работе → контроль» описан и согласован с интерфейсом.
- [ ] Интерфейс получает единые mobile-first токены, состояния и правила доступности.

### Out of Scope

- Автоматический регламент ТО — требуется проверенный источник, привязка к конкретной модификации и лицензия на данные.
- OCR чеков и заказ-нарядов — требует обработки файлов, извлечения данных и подтверждения пользователем.
- Рыночная цена, VIN-отчёты и отзывные кампании — не обещать без разрешённого поставщика и даты данных.
- Аккаунты, синхронизация, бэкапы и push-уведомления — текущий продукт сознательно хранит данные локально.
- Несколько автомобилей, топливо, маршруты и функции автопарка — не служат главному учебному сценарию.

## Context

- Кодовая база — статические `index.html`, `styles.css` и `app.js`; зависимости и сборка отсутствуют.
- Состояние хранится в `localStorage` под ключом `autoritm-v1`; приложение должно честно говорить о границах локальных данных.
- Исследование конкурентов и продуктовые решения — в `PRD.md`.
- Лекции, которые нужно учитывать: `../Лекции_Отус/Лекция_7/konspekt_lekcii_7.html`, `../Лекции_Отус/Конспект_Лекция_8.html`, `../Лекции_Отус/Лекция_9/Лекция_9_Проектируем_UX_конспект.html`.

## Constraints

- **Technology**: чистые HTML, CSS и JavaScript — сохраняем нулевую зависимость учебного прототипа.
- **Platform**: mobile-first веб — основные действия должны быть выполнимы одной рукой на маленьком экране.
- **Data integrity**: никакие внешние регламенты, цены или AI-выводы не имитируются как проверенные данные.
- **Privacy**: данные остаются в конкретном браузере, пока не появятся аккаунты и синхронизация.
- **Accessibility**: статус не передаётся только цветом; интерактивные элементы и текст сохраняют достаточный контраст.

## Key Decisions

|----------|-----------|---------|
| Один частный автомобиль — главная единица MVP | Сохраняет сценарий коротким и понятным для учебной валидации | — Pending |
| Ручной ввод — источник истины | Внешние данные пока не подключены и не должны притворяться достоверными | ✓ Good |
| Срок по дате или пробегу | Это ожидаемый паттерн из категории трекеров обслуживания | — Pending |
| Спокойная «цифровая сервисная книжка» | Отличает приложение от витрины продажи авто и снижает тревогу | — Pending |
| Тёмный хвойный + светлые поверхности + мятный акцент | Развивает уже реализованный визуальный язык и поддерживает доверительный тон | — Pending |
